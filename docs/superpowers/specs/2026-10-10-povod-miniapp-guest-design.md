# «Повод» — гостевой Telegram Mini App: спецификация дизайна

**Дата:** 2026-10-10
**Статус:** дизайн согласован с владельцем по частям; ждёт ревью этого документа
**Связано:** [MVP design](2026-10-08-povod-mvp-design.md), аудит
2026-10-09/10 (P0 бэкенда), референсы владельца (стриминг-витрина со
стеклянными панелями, карточки профиля dark/light, тёмное фото-приложение).

## 1. Цель

Mini App — одновременно **витрина клуба** (человек из анонса видит атмосферу
и сразу покупает) и **клубный кабинет** (билеты, голосования, напоминания).
Атмосфера — тёплое комьюнити, «свои люди», лёгкий юмор.

Критерии успеха v1:

- от анонса в чате до оплаты — не больше трёх экранов;
- QR виден сразу после подтверждённой оплаты и открывается без сети;
- проголосовать — два касания;
- гость не попадает в тупик: у каждой ошибки есть следующий шаг.

## 2. Решения владельца

| Тема | Решение |
|---|---|
| Фронтенд | Telegram Mini App, React + Vite + TypeScript, свои компоненты |
| Стиль | «Стеклянный вечер» (раздел 9), с нуля, без брендбука |
| Кабинет v1 | «Мои билеты» + напоминания + голосования; без истории посещений и лояльности |
| Голосования | голосуют все в клубе; 1 человек = 1 голос; менять можно до закрытия |
| Согласия | отдельного экрана нет; приветственное окно с текстом владельца, текст согласия владелец добавит сам |
| Рассылки | остаются в боте |
| Возвраты | только вручную админом (оферта: полный возврат более чем за 3 дня, позже — нет) |
| Поздняя оплата | всегда ручная сверка админом |
| Билеты друзьям | кнопка «Отправить другу»; билеты не именные |
| Управление | владелец с телефона — подпроект 2 |
| Вход | QR-ссылка в бота, сотрудник сканирует камерой — подпроект 3 |
| Сервер | свой VPS, Docker Compose |

## 3. Границы и подпроекты

Этот документ — **подпроект 1: гостевой Mini App**. Остальные идут отдельными
циклами «спека → план → реализация»:

1. гостевой Mini App (этот документ);
2. режим владельца в Telegram: мероприятия, постеры, голосования, продажи,
   ручные возвраты и сверка, рассылки;
3. вход по QR-ссылке в бота;
4. бэкенд P0 из аудита.

**Запуск v1 для гостей требует 2 и 4.** Без 4 не работают подтверждение
оплаты и билеты (webhook Т‑Банка, откат статусов, событие «билет выдан»,
освобождение брони при сбое Init, лимит активных броней). Без 2 некому
заводить мероприятия, постеры и голосования. Проектировать и верстать 1
можно параллельно.

**Порядок работ (решение владельца 2026-10-10: «с оплатой всё потом,
пока делаем визуал»):**

- **Этап A — визуал.** `webapp/` со всеми экранами, дизайн-системой и
  поведением Telegram на мок-данных: контракт раздела 5 реализуется
  локальным мок-слоем, оплата имитируется. Бэкенд и Т‑Банк не трогаем.
  Результат смотрим в браузере с эмуляцией Telegram, затем в Telegram.
- **Этап B — подключение.** Роутер `/api/app`, данные раздела 6, бот,
  реальная оплата — после подпроекта 4.

Не входит в v1: история посещений, лояльность, аватары других гостей
(персональные данные), именные билеты, оплата внутри Mini App без страницы банка.

## 4. Архитектура

```text
VPS ── Caddy (HTTPS, автосертификат)
        ├── /          → статика webapp (сборка Vite)
        ├── /api/*     → FastAPI (существующий)
        └── /media/*   → постеры (volume)
     ── bot, worker, postgres (как сейчас)
```

- Один домен: CORS не нужен. Образ Caddy собирает `webapp/` multi-stage.
- `webapp/` — React, Vite, TypeScript, официальный `telegram-web-app.js`
  с тонкой типизированной обёрткой (без стороннего SDK), TanStack Query,
  `lucide-react`, генерация QR на клиенте.
- Новый роутер `src/api/app/` с префиксом `/api/app`. Сервисы и
  репозитории — существующие; новые бизнес-правила — в `src/services/`.

### Аутентификация

Заголовок `Authorization: tma <initData>`. Зависимость проверяет подпись
ключом бота (`aiogram.utils.web_app.safe_parse_webapp_init_data`), отвергает
`auth_date` старше 24 часов, делает upsert пользователя по `telegram_id` и
кладёт его в запрос. Ошибка → 401, клиент показывает «Откройте приложение
из Telegram заново». Вне Telegram (браузер) — тот же экран.

## 5. API `/api/app`

| Метод | Назначение | Ответ (кратко) |
|---|---|---|
| `GET /me` | профиль, принят ли приветственный текст (версия), активный заказ | `{welcome_version_accepted, active_order}` |
| `POST /welcome/accept` | принять текущую версию приветствия | 204 |
| `GET /events?direction=` | опубликованные будущие, по дате | карточка: id, title, starts_at, timezone, address\|null, poster, min_price, seats_left, sold_out, direction |
| `GET /events/{id}` | карточка + типы билетов с остатком + голосование вечера | |
| `GET /directions` | активные направления для фильтра | |
| `POST /orders` | `{event_id, items:[{ticket_type_id, qty}]}` → бронь + Init | `{order_id, payment_url, expires_at}`; 409 `active_order_exists` с id; 409 `not_enough_seats` с остатком |
| `GET /orders/{id}` | статус для экранов ожидания/результата | `pending\|paid\|failed\|expired\|reconciliation` + таймер |
| `POST /orders/{id}/cancel` | снять бронь | 409, если платёж в неопределённом статусе |
| `GET /tickets` | мои: ближайшие, прошедшие, переданные, отменённые | QR-токен только для действующих |
| `POST /tickets/{id}/share` | ссылка «Отправить другу» | `{share_url}` |
| `DELETE /tickets/{id}/share` | отозвать незабранную ссылку | 204; 409, если уже забрали |
| `POST /tickets/claim` | `{share_token}` — друг забирает билет | билет друга |
| `GET /polls` | активные и недавно закрытые | варианты, мой голос, проценты после голоса |
| `PUT /polls/{id}/vote` | `{option_id}` — поставить или сменить голос | 409 `poll_closed` |

Все ответы — только данные текущего пользователя; id из пути проверяются на
владение (как в боте: пользователь из `initData`, не из параметров).

## 6. Данные (миграция 0009+)

- **Голосования:** `polls(id, event_id null, question, closes_at, status,
  created_by)`, `poll_options(id, poll_id, title, position)`,
  `poll_votes(poll_id, user_id, option_id, updated_at)`, уникальность
  `(poll_id, user_id)`. Голос меняется UPDATE до `closes_at`. «Все в
  клубе» = любой пользователь, принявший приветствие; билет не нужен.
- **Место уточняется:** `events.address` становится nullable. Когда админ
  задаёт адрес у опубликованного мероприятия, держателям билетов уходит
  сообщение бота «место определилось» (outbox, ключ `venue:<event>:<hash адреса>`).
- **Постеры:** `cover_ref` хранит ключ файла в `/media`; плюс
  `cover_focus_x/y` (0–1) для `object-position`. Обработка загрузки — в
  подпроекте 2.
- **Передача билета:** `tickets.holder_user_id` (null = покупатель),
  `ticket_shares(token_hash, ticket_id, created_by, claimed_by, claimed_at)`.
  Ссылка `t.me/<бот>/<app>?startapp=claim_<token>`; первый открывший
  становится держателем, у покупателя билет помечается «Передан» без QR.
  Повторно забрать нельзя; покупатель может отозвать ссылку, пока её не забрали.
  QR-токен при передаче не меняется: билеты не именные, проходит первый
  предъявивший (осознанное упрощение v1).
- **Короткий номер:** `tickets.short_code` — 4–6 цифр, уникален в
  пределах мероприятия; показывается под QR на случай нечитаемого кода.
- **Приветствие:** `users.welcome_version_accepted`, `welcome_accepted_at`.
  Какие согласия этим фиксируются, владелец решит, когда добавит текст.
- **Напоминания:** outbox-сообщения с ключами `reminder:24h:<ticket>` и
  `reminder:3h:<ticket>` — каждое уходит один раз на держателя билета.

## 7. Бот

- Menu Button открывает Mini App.
- Ссылки `startapp=event_<id> | order_<id> | ticket_<id> | claim_<token> | vote_<id>`.
- После оплаты — сообщение с кнопкой «Открыть билеты» (web_app).
- Напоминания за 24 и 3 часа, «место определилось», «бронь истекла».
- Поздняя оплата: «Оплата дошла после окончания брони. Администратор
  проверит и напишет вам сегодня» + задача админу (подпроект 2).

## 8. Экраны и поведение

**Каркас.** Вкладки «Афиша», «Билеты», «Голосуем» в плавающем меню.
`ready()`, `expand()`, `disableVerticalSwipes()` при старте. Высота —
`--tg-viewport-stable-height`, отступы — safe area и content safe area.
Стек навигации через history: deep link собирает «афиша → карточка».

**Старт.** Mini App запрашивает `GET /me`. Есть активный заказ → экран
ожидания или результата (не афиша). `start_param` — подсказка, не источник
истины; id заказа дублируется в `CloudStorage`. Не принято приветствие →
приветственное окно один раз, deep link после него не теряется.

**Афиша.** Hero ближайшего вечера, плитки направлений, «Скоро» сеткой 2×N.
Карточки: фото, дата, название, «от 1 550 ₽», «осталось N мест» / «мест нет».

**Карточка.** Фото-шапка со стеклянной «назад», заголовок, строка статов
(дата, время, места), «О вечере», голосование вечера, «Билеты» со
счётчиками −/+ (в странице, цели ≥44 px), итог «3 билета · 4 650 ₽»,
правило возврата мелко. Главное действие — **MainButton** «Оплатить N ₽»;
при нуле — неактивна «Выберите билеты»; мест нет — «Мест нет». Пока
MainButton видна, меню скрыто. После нажатия — `showProgress()`.

**Оплата.** `openLink(payment_url)`. С момента брони до её конца —
`enableClosingConfirmation()`. Экран ожидания: «Бронь ждёт оплаты»,
таймер, MainButton «Открыть оплату снова», ссылка «Отменить бронь»
(недоступна, пока платёж в неопределённом статусе). «Назад» не снимает
бронь: в афише плашка «Бронь ждёт оплаты · 08:12».

**Результат.** Успех → «Билеты у вас», MainButton «Показать билеты».
Ожидание подтверждения — опрос статуса до 60 с, затем «билет придёт
сообщением в бот». Неуспех — «Попробовать снова», если бронь жива.
«Назад» с результата — во вкладку «Билеты».

**Билеты.** Ближайшие сверху, «Прошедшие · N» свёрнуты; «Возвращён»,
«Передан», «Вечер отменён» — серым, без QR. Экран билета: QR на белой
плашке ≥240 px с полями, «Билет 2 из 3», свайп, короткий номер, «На карте»,
«Отправить другу». QR и данные билета кэшируются для офлайна.

**Голосуем.** Вопрос, варианты, тап = голос (haptic), после голоса —
проценты и «Можно передумать до чт, 16 окт, 18:00». Закрытые — итог.

**Haptic:** light на −/+, selection на фильтрах и голосе, success на
билете, warning на «мест меньше»/«бронь закончилась», error на неуспехе.

## 9. Визуальная система «Стеклянный вечер»

Тема — только `colorScheme` Telegram и `themeChanged`; `themeParams` не
используем, акцент клуба фиксирован. `setHeaderColor`,
`setBackgroundColor`, `setBottomBarColor` = `bg` текущей темы.

| Роль | Dark | Light |
|---|---|---|
| bg | #0F0E12 | #F6F3EE |
| surface 1 / 2 / 3 | #17151B / #1F1C24 / #2A262F | #FFFFFF / #F0ECE6 / #E6E1DA |
| text 1 / 2 / 3 | #F5F2EE / #BDB6AE / #8F8982 | #1D1A20 / #5A545C / #736D75 |
| accent / pressed / on-accent | #FF7A3D / #E8662B / #2B1205 | те же |
| accent-text | #FF7A3D | #B33F0B |
| иконки violet / mint | #9C8CFF / #5FD0A8 | #5B49D6 / #0E7A5B |
| success / error / warning | #5FD0A8 / #FF7A7A / #FFC857 | #0E7A5B / #C42B2B / #8A5A00 |
| border / strong | rgba(255,255,255,.08) / #6B655F | rgba(29,26,32,.10) / #8C868E |
| glass / glass-nav | rgba(30,27,34,.62) / rgba(48,44,52,.92) | rgba(255,255,255,.72) / rgba(255,255,255,.9) |

Все пары текст/фон проходят WCAG AA (≥4.5:1); оранжевый как текст на
светлом запрещён (2.59:1) — для этого `accent-text`.

**Типографика.** Unbounded 500: display 26/30 (капсом), h1 22/28, h2 17/22,
h3 14/18; не меньше 14 px. Manrope variable: body-l 16/24, body 15/22,
body-s 13/18 (500), caption/пилюли 12/16 (600), кнопка 16/20 (700), цена
17/22 (700, `tabular-nums`). Шрифты self-host woff2 (кириллица+латиница),
`font-display: swap`. Заголовки: `line-clamp` 2 в карточке, 3 в шапке;
длиннее 28 символов — на ступень меньше. Высоты только через `min-height`.

**Форма.** Радиусы 8 · 12 · 16 · 20 (hero, постеры) · 26 (шиты) · 999.
Отступы 2 · 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40; поля экрана 16, между
карточками 12, между секциями 24. Меню высотой 64 на `12px + safe-area`
снизу; контенту — `padding-bottom` ≥ 96 + safe-area. Тап-зоны ≥ 44 px.
Поверхности в тёмной теме разделяются бордером, не только заливкой.

**Стекло.** Контраст не зависит от blur: стекло — слой alpha ≥ .6.
`backdrop-filter: blur(14px) saturate(1.4)`; не больше двух стеклянных
слоёв на экране; не анимируется. Фолбэк `@supports not` и класс
`.no-blur` (`hardwareConcurrency ≤ 4` или `deviceMemory ≤ 3`) — непрозрачная
заливка surface 3. Пилюли на фото — rgba(15,14,18,.6) без blur.

**Фото.** Мастер 4:5 (≥800×1000) → постер 4:5, hero и шапка 2:1, полоса
билета 3:1, `object-fit: cover` + фокус-точка. Скрим снизу под текстом не
слабее .65 (на белом фото даёт 5.4:1) + лёгкая тень текста; текст на фото
всегда светлый. Короткая сторона < 600 px или нет фото — цветной блок
(цвет по хэшу названия из 8 проверенных: #5B2A86, #8A3A1A, #1F5C4D,
#7A2840, #2B3F7A, #7A5A14, #3E4A1F, #2F5F73) с иконкой направления.
Загрузка: средний цвет-плейсхолдер → fade 200 мс.

**Иконки.** Lucide, stroke 1.75, 20 px в пилюлях и статах, 24 px в меню и
плитках; активная вкладка — stroke 2 + акцент + подпись. Фиолетовый и
мятный — только для иконок статов рядом с текстом.

**Компоненты v1 и состояния:** Button (primary/outline: обычное, нажатие
scale .98, неактивное с подписью, загрузка с фиксированной шириной),
TabBar, DirectionTile (выбрано — акцент-рамка), Pill (accent, glass,
статусы), EventCard (нет фото, распродано — десатурация, skeleton),
PhotoHeader, Stepper (минимум/максимум, проверка остатка), OrderSummary,
PollOption (отправка, выбрано+проценты, закрыто, ошибка), StatusScreen,
TicketCard+Pager (действителен/использован/передан/отменён), EmptyState,
ErrorState, WelcomeScreen.

## 10. Тексты (ключевые)

Склонения через `plural()`: 1, 21 билет · 2–4 билета · 5–20 билетов;
«осталось 1 место / 2 места / 5 мест». Дата «чт, 16 окт», время «20:00»,
цена «1 550 ₽» (неразрывный пробел).

- Приветствие: «Привет, это «Повод»» / «Маленький клуб в Москве: киновечера,
  настолки, разговоры и вечеринки для своих. Здесь выбирают вечер, берут
  билет и голосуют, что смотрим и во что играем.» / [текст владельца] /
  кнопка «Заходим».
- Пустая афиша: «Пока тихо» / «Новых вечеров нет. Как появятся, напишем в боте.»
- Ожидание: «Бронь ждёт оплаты» / «Места за вами ещё 08:42».
- Успех: «Билеты у вас» / «Ждём в чт, 16 окт в 20:00. Копия ушла в бот.»
- Банк молчит: «Банк отвечает дольше обычного» / «Если оплата прошла,
  билет придёт сообщением в бот. Страницу можно закрыть.»
- Неуспех: «Оплата не прошла» / «Деньги не списаны. Бронь ещё держим — 6 минут.»
- Нет сети: «Нет связи» / «Проверьте интернет. Оплаченные билеты никуда не денутся.»
- Бронь истекла: «Бронь закончилась» / «Десять минут прошли, места вернулись в продажу.»
- Мест меньше: «Мест стало меньше» / «Пока вы выбирали, осталось 2 места.
  Взять 2 билета?» / «Взять 2» · «Изменить».
- Пустые билеты: «Билетов пока нет» / «Выберите вечер в афише — билеты появятся здесь.»
- Пустые голосования: «Сейчас ничего не выбираем» / «Новое голосование появится — напишем в боте.»
- Бот, за сутки: «Завтра, чт, 16 окт, в 20:00 — «Киновечер». У вас 2 билета.
  Место: [адрес]. Увидимся.»
- Бот, за 3 часа: «Сегодня в 20:00 — «Киновечер». Через 3 часа встречаемся:
  [адрес]. Билет держите под рукой, на входе сканируем с телефона.»

## 11. Пограничные случаи

| Случай | Поведение |
|---|---|
| Двойное «Оплатить» | `showProgress()` сразу; сервер возвращает ту же бронь |
| Бронь уже есть (другое устройство) | 409 → «У вас уже есть бронь на «…». Продолжить оплату или отменить?» |
| Закрыл Mini App на странице банка | при открытии — ожидание или «Билеты у вас» по статусу |
| Telegram не вернул гостя | билет придёт в бот; в Mini App — по `GET /me` |
| Оплата после истечения брони | статус `reconciliation`: «Оплата дошла после окончания брони. Администратор проверит и напишет вам сегодня» |
| Банк молчит > 60 с | «Отменить бронь» недоступна до определённого статуса |
| Мест стало меньше при оплате | 409 с остатком → диалог «Взять N» |
| Вечер отменили | билет серый без QR, «Вечер отменён. Деньги вернём, напишем в боте» |
| Место определилось / изменилось | сообщение бота + «Новое место» на билете |
| Друг открыл ссылку | билет переходит другу; у покупателя «Передан» |
| Ссылку открыл сам покупатель | ничего не меняется |
| Нет сети на входе | QR из кэша, подпись «Билет сохранён на телефоне» |
| Старый клиент без MainButton/CloudStorage | кнопки в странице, `localStorage` |
| Открыто вне Telegram | экран «Откройте из Telegram» со ссылкой на бота |

## 12. Доступность

Статус не только цветом (слово + иконка); контраст ≥ 4.5:1 в обеих темах;
таймер `role="timer"` с озвучкой на 5, 2, 1 и 0 минут и текстом «до 20:12»;
−/+ ≥ 44×44 с `aria-label`; вёрстка в rem, выдерживает масштаб 200%;
`prefers-reduced-motion` отключает анимации; haptic не единственный сигнал;
QR дублируется коротким номером.

## 13. Тестирование

- Бэкенд (pytest на PostgreSQL, как сейчас): проверка `initData` (подпись,
  срок, подмена), владение во всех `/api/app/*`, лимит одной брони,
  409-сценарии, голос/смена голоса/закрытие, передача билета (claim один
  раз, отзыв), напоминания и «место определилось» идемпотентны, HTTP-тесты
  самих маршрутов (не только сервисов).
- Фронтенд: Vitest для `plural()`, форматов даты/цены, редьюсера корзины и
  машины состояний оплаты; Playwright с моком Telegram WebApp для пути
  «афиша → оплата → результат → билет» и офлайн-QR.
- Ручная проверка на iOS, Android (включая слабый) и Telegram Desktop:
  возврат из банка, тёмная/светлая тема, крупный системный шрифт.
- CI: сборка `webapp`, линт, тесты, сборка образа Caddy.

## 14. Риски и открытые вопросы

- Подключена ли онлайн-касса на терминале (влияет на Init и уведомления
  `RECEIPT`) — владелец проверяет в кабинете Т‑Бизнеса.
- Для бота нужен отдельный магазин/терминал Т‑Банка для интеграции по API.
- Тексты согласий и оферты (упоминание бота и Mini App) — за владельцем.
- Качество визуала зависит от постеров: к каждому мероприятию нужно фото.
- Поздняя оплата требует исправления P0 №7: из `reconciliation` админ
  должен уметь выдать билет или вернуть деньги.
