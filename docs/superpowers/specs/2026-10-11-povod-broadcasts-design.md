# Рассылки в режиме владельца и сегментация аудитории — дизайн

Дата: 2026-10-11. Статус: на проверке у владельца.

## 1. Зачем

Владелец сам пишет и отправляет рассылки гостям бота с телефона — без разработчика и без API. Аудиторию выбирает по поведению гостей: кто идёт, кто лайкнул, кто был, кто что любит. Сообщения приходят гостям **в чат бота**; Mini App — только пульт.

Критерии успеха:

- от «Новая рассылка» до отправки 200 гостям — меньше 3 минут с телефона;
- перед отправкой владелец видит точное число получателей и сообщение так, как его увидит гость;
- ни один гость не получает больше двух рассылок в неделю и ничего не получает ночью;
- после отправки видно: доставлено, нажали кнопку, купили.

## 2. Решения владельца (2026-10-11)

| Вопрос | Решение |
|---|---|
| Где пульт | Режим владельца в Mini App, раздел «Рассылки» рядом с «Мои вечера» |
| Сегменты v1 | идут на вечер; лайкнули; были; покупали / ни разу; направление; все; комбинация «лайкнули, но не купили» |
| Формат сообщения | текст с оформлением + одна картинка (афиша или своя) + до двух кнопок («Открыть вечер» или ссылка). Подстановок `{имя}` нет |
| Шаблоны | 5 готовых + сохранить рассылку как шаблон + создать шаблон с нуля |
| Конструктор аудитории | фильтры-переключатели, условия через «И», живой счётчик |
| Анти-спам | не больше 2 рассылок гостю за 7 дней; тихие часы 22:00–10:00 МСК |
| Право доступа | `manage_campaigns` (уже есть в `src/services/admin/permissions.py`) |
| Отписка | кнопки отписки нет (решение 2026-10-11); прежние отказы в БД уважаются |

Не входит: возвращалки и сегмент «давно не заходили», сегмент «пришли по ссылке», A/B-тесты, веб-админка на компьютере, подстановка имени, «прочитали».

## 3. Экраны (Mini App, режим владельца)

Вход: Кабинет → Режим владельца → вкладка «Рассылки» (видна только при `manage_campaigns`).

**Список.** Фильтры «Черновики / Запланированы / Отправлены». Карточка: название, дата отправки, «214 гостей», после отправки «доставлено 209 · нажали 37». Кнопка «Новая рассылка». Вкладка «Шаблоны».

**Старт новой рассылки.** Выбор: готовый шаблон / свой шаблон / с чистого листа.

**Редактор** — один экран сверху вниз:

1. Название (видно только владельцу).
2. Вечер — необязательно. Выбор подставляет афишу, кнопку «Открыть вечер» и название вечера в текст шаблона (подстановка в момент выбора, не при отправке).
3. Текст: жирный, курсив, ссылка; счётчик символов (1024 с картинкой, 4096 без).
4. Картинка: афиша вечера / загрузить свою / без картинки.
5. Кнопки, до двух: «Открыть вечер» (если вечер выбран) или ссылка (подпись + https-адрес).
6. Аудитория: фильтры (раздел 5) и счётчик «Получат N» (обновляется с задержкой ~300 мс после изменения).
7. Предпросмотр — пузырь сообщения Telegram.

Действия: «Отправить себе», «Сохранить черновик», «Сохранить как шаблон», «Отправить…» → «Сейчас / Запланировать (дата, время)» → подтверждение «Отправить 214 гостям?». Ночью «Сейчас» предлагает «Отправить в 10:00?».

**Запланированная** — правка и «Отменить рассылку». **Идущая** — «Остановить». **Отправленная / остановленная** — только чтение + статистика + «Повторить» (копия в черновик).

**Шаблоны.** Готовые — только «Использовать» / «Скопировать в свои». Свои — создать, править, удалить.

Голос интерфейса — как в остальном Mini App (на «ты», `copy.test.ts`).

## 4. Данные

### 4.1 Лайки на сервере

Таблица `favorites`: `user_id`, `event_id`, `created_at`; PK (`user_id`, `event_id`). Снятие лайка — удаление строки.

`/api/app` (авторизация `initData`, как остальной `/api/app`):

- `PUT /favorites/{event_id}` — поставить (идемпотентно);
- `DELETE /favorites/{event_id}` — снять (идемпотентно);
- `GET /favorites` — список id;
- `POST /favorites/import` — `{eventIds: [...]}`, до 200 id, разовый перенос из `localStorage`; неизвестные и неопубликованные id молча пропускаются.

Mini App: лайк пишется локально и на сервер; при ошибке сети — повтор при следующем открытии. Первый запуск новой версии — `import`, затем флаг «перенесено» в `localStorage`.

### 4.2 Рассылка (расширение `campaigns`)

Новые поля:

- `title` (поле есть) — название для владельца;
- `body` — текст в Telegram HTML (только `b`, `i`, `a href`);
- `image` — `{kind: "event"|"upload"|"none", ref}`;
- `buttons` — до 2: `{kind: "event"|"url", label, url?}`;
- `event_id` — nullable;
- `audience` — фильтры (раздел 5), JSONB (поле есть);
- `status` — `draft → scheduled → running → completed | cancelled | stopped`;
- `scheduled_at`, `started_at`, `finished_at`;
- `recipient_count` — размер замороженного списка.

Тексты подписей кнопок и `body` валидируются по длине и по допустимым тегам на сервере.

### 4.3 Получатели

Существующая таблица `campaign_deliveries` и есть замороженный список: при старте в неё пишутся все получатели сразу. Статусы расширяются: `queued | sent | blocked | failed | skipped_limit`. Поля `error`, `sent_at`, `provider_message_id` уже есть.

### 4.4 Шаблоны

Таблица `campaign_templates`: `id`, `name`, `body`, `image_kind`, `buttons`, `is_builtin`, `created_by`, `updated_at`. Пять готовых создаются миграцией (раздел 8), `is_builtin = true` — не правятся и не удаляются через API.

### 4.5 Клики

Таблица `campaign_clicks`: `campaign_id`, `user_id` (nullable), `button_index`, `clicked_at`. Короткие ссылки `link_code` (`campaign_id`, `button_index`, `url`).

### 4.6 Картинки

Загрузка как у афиш вечеров (`src/services/media`): WebP, EXIF вычищен, sRGB, `MEDIA_ROOT/campaigns/`. Для Telegram отправляется версия 1080.

## 5. Сегменты

Фильтр аудитории (`audience`):

```json
{
  "event": {"id": "<uuid>", "relation": "going|liked|liked_not_bought|attended"},
  "directionId": "<uuid>",
  "purchases": "any|bought|never"
}
```

Все поля необязательны; пустой фильтр = все. Условия через «И».

| Условие | Определение |
|---|---|
| `going` | есть билет `issued` или `checked_in` на вечер |
| `attended` | есть билет `checked_in` на вечер |
| `liked` | вечер в `favorites` |
| `liked_not_bought` | вечер в `favorites` и нет оплаченного заказа на него |
| `directionId` | хотя бы один билет, лайк или посещение вечера этого направления |
| `bought` / `never` | есть / нет заказа `PAID` (уже есть в `SegmentService`) |

Всегда исключаются: `users.is_blocked`, последний статус согласия `marketing = revoked`.

`POST /api/owner/campaigns/audience-count` → `{count}` — для счётчика; тот же код, что и заморозка.

## 6. Отправка

Основа — существующие `CampaignDeliveryWorker`, `Outbox`, `CampaignOutboxWorker`.

1. **Заморозка.** При старте (немедленном или в `scheduled_at`) сервер в одной транзакции резолвит фильтр и пишет все строки `campaign_deliveries`; `recipient_count` фиксируется. Дальше фильтр не пересчитывается.
2. **Лимит.** При заморозке гость, получивший ≥ 2 рассылки (`sent`) за последние 7 дней, получает статус `skipped_limit`. Сообщения о билетах (сервисные) в лимит не входят — они не идут через кампании.
3. **Тихие часы.** `scheduled_at` в 22:00–10:00 МСК сервер отклоняет (ошибка с полем). Старт «сейчас» ночью — API возвращает предложение ближайших 10:00; клиент переспрашивает.
4. **Сообщение.** С картинкой — `sendPhoto` с подписью (HTML); без — `sendMessage` (HTML, без превью ссылок). Кнопки — inline: «Открыть вечер» — `url` на `t.me/<бот>/<app>?startapp=event_<eventId>_c<campaignShortId>`; ссылка — `url` на `<домен>/r/<code>`.
5. **Скорость.** ≤ 25 сообщений/с на процесс; на `429` ждать `retry_after` и продолжить; `403 Forbidden: bot was blocked` → получатель `blocked`, `users.is_blocked = true`.
6. **Отправить себе.** Сразу, тем же рендером, владельцу (его `telegram_id`), без лимита и тихих часов, не пишется в статистику.
7. **Отмена / остановка.** `scheduled` → `cancelled`. `running` → `stopped`: оставшиеся `queued` не отправляются.
8. **Аудит.** `owner.campaign.create|update|schedule|start|cancel|stop`, `owner.template.*` — как у вечеров.

Mini App: разбор `startapp=event_<id>[_c<campaign>]` → открыть экран вечера; при наличии `_c` — `POST /api/app/campaign-open {campaign}` (запись клика по кнопке 0).

## 7. API режима владельца

Префикс `/api/owner`, вход по `initData`, право `manage_campaigns`, формы ошибок — как у событий (`{message[, field]}` и др.), версия `updatedAt` для правок.

- `GET /campaigns?filter=draft|scheduled|sent`, `GET /campaigns/{id}`
- `POST /campaigns`, `PATCH /campaigns/{id}` (только `draft` и `scheduled`)
- `POST /campaigns/{id}/image` (multipart), `DELETE /campaigns/{id}/image`
- `POST /campaigns/{id}/test` — отправить себе
- `POST /campaigns/{id}/send` `{at?: iso}` — сейчас или запланировать
- `POST /campaigns/{id}/cancel`, `POST /campaigns/{id}/stop`
- `POST /campaigns/{id}/duplicate`
- `GET /campaigns/{id}/stats`
- `POST /campaigns/audience-count`
- `GET /campaign-templates`, `POST /campaign-templates`, `PATCH /campaign-templates/{id}`, `DELETE /campaign-templates/{id}`, `POST /campaigns/{id}/save-as-template`

Публично: `GET /r/{code}` → запись клика → 302 на `url`.

Существующий `src/api/admin/campaigns.py` (cookie-админка) остаётся как есть; новый роутер — в `src/api/owner/`.

## 8. Готовые шаблоны (черновик, финал — копирайтер на этапе плана)

Голос — `docs/brand/bot-entry-copy.md`. `{event}`, `{date}` подставляются при выборе вечера в редакторе.

1. **Новый вечер в афише** — «{date} у нас «{event}». Места уже можно брать.» Кнопка «Открыть вечер».
2. **Осталось мало мест** — «На «{event}» осталось совсем немного мест. Сейчас самое время.»
3. **Завтра вечер** — «Завтра «{event}». Если билета ещё нет, он тут.»
4. **Спасибо, что пришли** — «Спасибо, что были на «{event}». Следующий вечер уже в афише.»
5. **Вечер отменён / перенесён** — «С «{event}» поменялись планы. Все подробности по кнопке.»

## 9. Статистика

`GET /campaigns/{id}/stats`:

- `recipients` — замороженный список;
- `delivered` — `sent`;
- `failed` — `blocked` + `failed`, с разбивкой по причинам;
- `skippedLimit`;
- `clicked` — уникальные гости с кликом (кнопка «Открыть вечер» — через `campaign-open`, ссылки — через `/r/`; анонимные клики `/r/` считаются отдельно числом);
- `bought` — получатели, оплатившие заказ на `event_id` в течение 7 дней после `started_at` (только если вечер выбран). Без выручки.

## 10. Ошибки и пограничные случаи

| Случай | Поведение |
|---|---|
| Вечер рассылки сняли с публикации / отменили до старта | старт отклоняется: «Вечер больше не опубликован» |
| Получателей 0 | «Отправить» неактивна, «Получат 0» |
| Картинка не загрузилась в Telegram | повтор без картинки не делаем; получатель `failed`, причина в статистике |
| Две вкладки правят одну рассылку | 409 по `updatedAt`, как у вечеров |
| Владелец без `telegram_id` | «Отправить себе» недоступна |
| Падение воркера посреди рассылки | продолжает с `queued`; дубликаты исключены ключом `campaign:<id>:user:<id>` |
| Ссылка в кнопке не https | 422 с полем |

## 12. Порядок работ

1. **План 1 — бэкенд:** `favorites` + `/api/app/favorites`, сегменты, шаблоны (+ миграция готовых), API кампаний, отправка (заморозка, лимит, тихие часы, фото и кнопки, 429/403), клики и `/r/`, статистика.
2. **План 2 — экраны «Рассылки» на моках** в режиме владельца.
3. **План 3 — подключение:** HTTP-клиент рассылок, лайки на сервер и перенос, разбор `startapp`.

Каждый план — отдельная сессия.
