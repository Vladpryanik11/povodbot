# Повод — режим владельца: события и постеры

**Статус:** дизайн согласован с владельцем по разделам (сессия 2026-10-11); ждёт ревью этого документа.
**Подпроект 2, цикл 1** из спеки `2026-10-10-povod-miniapp-guest-design.md` (§1: «режим владельца в Telegram»).

## 1. Цель

Владелец клуба с телефона, внутри Telegram, заводит и правит события, загружает и меняет постеры, публикует и снимает с публикации — без разработчика и без Swagger.

Успех: владелец создаёт событие с фото и билетами, видит его глазами гостя и публикует; меняет фото у опубликованного события — гости видят новое.

## 2. Решения владельца

| Тема | Решение |
|---|---|
| Объём цикла | события + постеры. Голосования, продажи/чек-ин, возвраты, рассылки — следующими циклами |
| Где | в том же Mini App: пункт «Режим владельца» в Кабинете, только для админов |
| Этап | бэкенд и экраны сразу; экраны на моках, подключение webapp к API — общий этап B |
| Фото | обработка на сервере (подход A), хранение — volume на VPS, отдаёт Caddy (`/media/*`) |

Вне объёма: удаление событий, копирование, повторяющиеся события, отмена с возвратами, рассылка «место определилось», чистка осиротевших файлов.

## 3. Экраны (webapp)

Та же тёмная дизайн-система v2, голос на «ты».

1. **Мои вечера** — список, фильтр «Все / Черновики / Прошли». Строка: миниатюра постера (или заглушка «нет фото»), название, дата, статус-пилюля («Опубликовано · 18/30», «Черновик», «Черновик · нет фото»). Кнопка «+ Новый вечер».
2. **Событие** — одна форма со скроллом: постер («Сменить фото»), направление, когда (начало–конец), где (адрес или переключатель «Место уточняется»), ссылка на карту, описание, вместимость, цвет-акцент (необязательно), типы билетов строками «название · цена · сколько» (добавить / выключить). Сохранение кнопкой «Сохранить», без автосейва. «Как видит гость» открывает настоящий экран события с текущими данными формы. «Опубликовать» доступна при полной форме и наличии фото; иначе подсказывает, чего не хватает. У опубликованного — «Снять с публикации».
3. **Постер** — выбор фото из галереи, затем «Тапни на главное»: точка фокуса и живые превью обрезки 4:5 (ряд «Скоро»), 16:9 (ряд «На этой неделе»), 3:1 (билет). «Готово» загружает.

Пункт в Кабинете виден, только если `GET /api/owner/me` вернул роль с `manage_events`.

## 4. API и данные

### Аутентификация

Роутер `src/api/owner/`, префикс `/api/owner`. Зависимость проверяет `Authorization: tma <initData>` (подпись ключом бота, `auth_date` не старше 24 часов), находит активного `admin_users` по `telegram_id`. Нет админа или нет права `manage_events` — 403. Каждое изменяющее действие пишется в `admin_audit_logs` с этим админом как исполнителем. Парольный `/api/admin/*` остаётся без изменений.

Привязка первого владельца — только на сервере:
`python -m scripts.link_admin_telegram --login <login> --telegram-id <id>`.

### Эндпоинты

| Метод | Назначение |
|---|---|
| `GET /api/owner/me` | роль и права |
| `GET /api/owner/directions` | направления |
| `GET /api/owner/events?filter=all\|draft\|past` | список: статус, продано/мест, постер |
| `GET /api/owner/events/{id}` | форма целиком, с типами билетов и `updated_at` |
| `POST /api/owner/events` | создать черновик |
| `PATCH /api/owner/events/{id}` | сохранить; тело несёт `updated_at` как версию |
| `POST /api/owner/events/{id}/publish` | опубликовать |
| `POST /api/owner/events/{id}/unpublish` | вернуть в черновик |
| `POST /api/owner/events/{id}/poster` | multipart: `file`, `focus_x`, `focus_y` |
| `PATCH /api/owner/events/{id}/poster-focus` | сменить только фокус |

Роутер — тонкая обёртка над `EventService`; новые правила — в `src/services/`.

Постер в ответах — в форме `Poster` из `webapp/src/api/types.ts`: `{url, focusX, focusY, width, height}`, `url` указывает на вариант 1080.

### Миграция 0009

- `admin_users.telegram_id` — `bigint`, unique, nullable.
- `events.cover_focus_x`, `events.cover_focus_y` — `numeric`, 0–1, default 0.5, check-ограничение диапазона.
- `events.cover_width`, `events.cover_height` — `int`, nullable: размеры варианта 1080 для `Poster.width/height`.
- `events.accent_color` — `varchar(7)`, nullable, check `^#[0-9A-Fa-f]{6}$`.
- `events.address` — nullable (null = «Место уточняется»).
- `events.cover_ref` хранит ключ `posters/<sha256>`, не URL. Существующие значения-URL отдаются как есть.

### Правила событий

- Черновик создаётся по текущей валидации `EventService` (`validate` в `src/services/events/service.py`), с одним послаблением: адрес необязателен.
- **Публикация требует постер.** Пустой адрес публиковать можно.
- **Снять с публикации** (published → draft) — только если у события нет ни одной брони и ни одного билета; иначе 409 с текстом «Уже есть брони — отменить можно будет через возвраты».
- После продаж — как сейчас: вместимость и лимиты не ниже занятого; цену менять можно, купленных билетов это не касается.
- Конфликт версий: `updated_at` в `PATCH` не совпал с текущим — 409 «Событие уже изменили — обнови».

## 5. Обработка фото

Модуль `src/services/media/posters.py`; зависимости Pillow и `pillow-heif`.

1. Размер тела ≤ 15 МБ; сигнатура — JPEG, PNG, WebP или HEIC/HEIF. Иначе 415/413.
2. `Image.open` с `MAX_IMAGE_PIXELS` = 40 Мп; `ImageOps.exif_transpose`; перевод в RGB.
3. Меньше 800×1000 — 422 «Фото маловато — нужно хотя бы 800×1000». Пропорции не проверяются: обрезка идёт по фокусу.
4. Варианты WebP, качество 82, без метаданных: ширина 480, 1080 и мастер с длинной стороной ≤ 2000 (меньшие не увеличиваются). Ключ — sha256 байтов мастера; файлы `/media/posters/<hash>-480.webp`, `-1080.webp`, `-master.webp`. Запись через временный файл и `os.replace`. Если файлы с этим хешем уже есть — не пишем заново.
5. `cover_ref`, фокус и аудит меняются одной транзакцией. Старые файлы не удаляются.
6. Обработка в `run_in_threadpool`; одновременно не больше одной загрузки на админа (иначе 429).

Caddy: `/media/*` из volume, `Cache-Control: public, max-age=31536000, immutable`. Путь volume — настройка `MEDIA_ROOT`.

## 6. Ошибки в Mini App

- Нет сети: «Нет связи — данные не потерялись, попробуй ещё раз»; форма хранит ввод в памяти.
- Валидация: сервер отдаёт `{field, message}`, текст под полем.
- 409 (снятие с публикации, конфликт версий) и ошибки фото (413/415/422/429) — понятные подписи в форме и шите фото.

## 7. Тесты

**Бэкенд (pytest):** initData — валидная, просроченная, чужая подпись, не админ, роль без права; список и фильтры; создание, правка, публикация без постера и с ним; unpublish с бронью и без; конфликт версий; загрузка — HEIC, EXIF с GPS удаляется, повёрнутое фото, маленькое, не картинка, бомба распаковки, повтор того же файла; аудит. Реальных запросов к Т‑Банку и Telegram нет; initData подписывается тестовым ключом.

**Webapp (vitest):** `OwnerApi` с мок-реализацией в стиле `MockApi`; экраны списка, формы, фокуса; пункт Кабинета только для админа; тексты ошибок. В конце — ручная проверка в браузере с эмуляцией Telegram.

## 8. Порядок работ

Два плана, две сессии:
1. **Бэкенд:** миграция 0009, `/api/owner`, обработка фото, скрипт привязки, тесты.
2. **Экраны:** `OwnerApi` + моки по контракту §4, три экрана, тесты.

Подключение webapp к реальному API — общий этап B.
