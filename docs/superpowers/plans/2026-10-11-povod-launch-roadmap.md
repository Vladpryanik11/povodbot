# «Повод» — чего не хватает до запуска и план

Дата: 2026-10-11. Это дорожная карта, не пошаговый план: у каждой фазы перед стартом
будет свой план (`superpowers:writing-plans`), а у фаз 4–5 сначала спека
(`superpowers:brainstorming`). Правила токенов из `CLAUDE.md` действуют: одна фаза —
одна сессия (или две), контекст < 200k, сабагентов 0–2 на Sonnet.

## Где мы сейчас

Готово: визуал гостевого Mini App v2 на моках (175 тестов), режим владельца — бэкенд
(афиши, события, публикация) и экраны на моках (241 тест). Бэкенд: 358 тестов.

Не готово главное: **ничего из этого не подключено друг к другу и к деньгам.**
Mini App живёт на `MockApi`, а настоящий бэкенд до сих пор не умеет ни принять
оплату в боевых условиях, ни отдать Mini App данные.

### B. Бэкенд для Mini App (`/api/app` — нет вообще)

- Нет роутера и зависимости `initData` для гостя (для владельца есть — `src/api/owner/auth.py`, переиспользовать).
- Нет данных: голосования (`polls*`), передача билета (`ticket_shares`, `holder_user_id`),
  короткий номер `short_code`, `show_in_attendees`,
  `events.accent_color`, возраст и время входа, `attendees {count, avatars}`.
- Нет эндпоинтов: `me`, `events`, `orders` (+ идемпотентный повтор), `tickets`,
  `share`/`claim` (claim должен быть идемпотентным для того же пользователя), `polls`/`vote`.
- Публичный `/api/public/events` отдаёт сырой `cover_ref`; нужен `poster_out` → `Poster`.
- Нет настроек `BOT_USERNAME`, `WEBAPP_URL`.

### C. Подключение фронта

- `HttpAppApi` и `HttpOwnerApi` (`fetch`, `Authorization: tma …`, `parseOwnerError`) вместо моков; подмена в `main.tsx`.
- Возврат со страницы банка в Mini App, `start_param`-ссылки, CloudStorage с проверкой версии клиента.
- E2E (Playwright с моком Telegram): афиша → оплата → результат → билет; офлайн-QR.

### D. Вход на вечер (подпроект 3 — спеки нет)

Решение владельца: QR-ссылка в бота, сканирует телефон персонала. Не хватает: спеки,
роли «вход» (`?owner=entrance` есть только на моках), check-in с причинами отказа и
именем гостя, списка «вечера сегодня» для персонала, проверки статуса вечера при входе
(отменённый сейчас пускает).

### E. Режим владельца — остаток (подпроект 2)

Сделаны вечера и афиши. Нет: голосования, список заказов и платежей, очередь проблемных
(`RECONCILIATION_REQUIRED`, `REFUND_UNKNOWN`), ручной возврат и сверка из интерфейса,
отмена вечера (возвраты + аннулирование + уведомления), рассылки (аудитория, расписание,
отписка), закрытие продаж типа билета при наличии продаж, создание первого owner.

### F. Бот

Menu Button → Mini App; `startapp`-ссылки (`event_`, `order_`, `ticket_`, `claim_`, `vote_`);
сообщение «Открыть билеты» после оплаты; напоминания за 24 и 3 часа; «бронь истекла»;
«место определилось»; поздняя оплата; обработчик ошибок; московское время; `/stop`;
атрибуция (deep link не открывает вечер, START пишется при каждом «Главном меню»).

### G. Инфраструктура и эксплуатация

VPS и домен с HTTPS; образ Caddy, собирающий `webapp/` (статика + `/api` + `/media` с
`Cache-Control: immutable`); лимит тела запроса ~16 МБ; Pillow 12.x; память под фото 40 Мп
(~300–400 МБ пик); рабочие backup/restore (скрипты не исполняемые, URL `+asyncpg`, пароль
в argv, `--single-transaction`); логи/метрики/алерты (сейчас `/metrics` пуст, логгера в
`src/` нет); Compose проверен настоящим Docker в CI; тест прав на файлы афиш на Linux;
чистка осиротевших афиш.

### H. Решения и материалы владельца (блокируют, код не нужен)

1. Касса 54-ФЗ на терминале: подключена ли, шлёт ли чеки автоматически (кабинет Т-Бизнеса).
2. Отдельный терминал/магазин Т-Банка для API; `TerminalKey`, пароль, sandbox; одно- или двухстадийная оплата.
3. VPS и домен; боевой токен бота, `@username`, регистрация Mini App в BotFather.
4. Тексты: согласие на ПДн (приветствия в приложении нет — решить, где брать), оферта (с упоминанием бота и Mini App), политика ПДн,
   контакт поддержки, возраст по вечерам (сейчас «18+» константой), список направлений.
5. Telegram ID первого owner и людей на входе.
6. Пушить ли `main` на GitHub (отстаёт на 68 коммитов).
7. Что входит в первый пилотный вечер (см. «Что можно вынести»).

## Что можно вынести из пилота (решение владельца)

Чтобы выйти на первый вечер раньше, без этого можно жить:

- голосования (фаза 4, часть про polls) и экраны их создания;
- рассылки из режима владельца (в боте остаются рассылки по готовому коду);
- передача билета другу (`share`/`claim`);
- аватары «кто идёт», `attendees`;
- частичные возвраты, удаление/обезличивание данных (но 152-ФЗ: отзыв согласия нужен до запуска).

Нельзя выносить: фазы 1, 2, 3, 5, 6, 9, 10 и «продажи» из фазы 8 в минимальном виде.

## Риски

- Контракт T-Bank проверен только по документации; реальные расхождения вылезут в sandbox (фаза 10) — поэтому sandbox-смоук лучше сделать сразу после фазы 1, не ждать конца.
- Без кассы 54-ФЗ продажа и возврат без чека — юридический риск владельца, не код.
- Пик памяти при обработке афиш может не поместиться в маленький VPS.
- Бот работает на polling: второй инстанс даст конфликт — держать один.
